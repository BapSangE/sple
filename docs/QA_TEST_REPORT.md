# Sple 서비스 통합 QA 테스트 보고서

## 1. 테스트 환경
- Frontend: `http://localhost:3000` (Next.js 14)
- Backend: `http://127.0.0.1:8000` (FastAPI)
- 테스트 방식: 브라우저 에이전트를 통한 End-to-End 플로우 시뮬레이션 및 터미널 로그 분석

## 2. 테스트 결과 (발견된 이슈 목록)

### 🔴 이슈 1: 네이버 지도 렌더링 실패 (Open API 인증 에러)
- **증상**: 메인 화면 및 `Map` 컴포넌트 호출 시 지도 영역이 회색으로 표시됨.
- **원인**: 브라우저 콘솔 확인 결과 `네이버 지도 Open API 인증이 실패했습니다. 클라이언트 아이디와 웹 서비스 URL을 확인해 주세요.` 에러가 발생했습니다.
- **분석**: `NEXT_PUBLIC_NAVER_CLIENT_ID`는 환경 변수에 올바르게 적용되어 있으나, Naver Cloud Platform (NCP) 콘솔의 'Web 서비스 URL' 설정에 `http://localhost:3000`이 등록되어 있지 않아 발생하는 CORS/인증 문제로 보입니다.

### 🔴 이슈 2: 인스타그램 링크 추출(Scraping) 실패
- **증상**: 추출 탭(`/add`)에서 인스타그램 링크(`https://www.instagram.com/p/DFzL1QSTwJ7/`) 입력 후 "AI 분석하기" 실행 시 약 20초 뒤 "앗! 장소 정보를 찾지 못했어요" 에러 메시지가 출력됨.
- **원인**: 백엔드 로그 확인 결과 Jina Reader(`r.jina.ai`)가 정상적으로 HTTP 200을 반환하고 Gemini 플로우까지 넘어갔으나, 인스타그램 자체의 비로그인 접근 차단(로그인 월)으로 인해 Jina Reader가 본문을 긁어오지 못하고 빈 값을 반환한 것으로 추정됩니다. (직접 텍스트를 입력하는 경우 정상적으로 추출 성공)

### 🔴 이슈 3: 바텀 시트 내 구글 애드센스(AdBanner) 누락
- **증상**: 장소 추출이 성공하여 결과창(바텀 시트 형식)이 나타날 때, 리스트 하단에 구글 애드센스 배너가 보이지 않음.
- **분석**: `src/app/add/page.tsx`의 렌더링 코드(Step 3 Result 영역)를 확인한 결과, `AdBanner` 컴포넌트가 삽입되어 있지 않은 설계 누락 상태입니다.

### 🔴 이슈 4: 추출된 장소 클릭 시 네이버 지도로 즉시 이동하는 로직 누락
- **증상**: 추출 결과 리스트에서 장소를 클릭할 경우 "선택/체크해제(Check)" 기능만 작동하고, 기획서(Rule 4)에 명시된 "네이버 지도로 이동하는 플로우"가 실행되지 않음.
- **분석**: 저장된 리스트 화면(`/saved`)에서는 `handleNaverMap` 함수를 통해 네이버 지도로 연결하는 로직이 있으나, 추출 직후의 화면(`/add`)에는 해당 로직이 연결되어 있지 않습니다.

## 3. 후속 작업 제안
1. **네이버 지도**: NCP 콘솔 접속 후 `http://localhost:3000` URL 추가 등록 필요 (사용자 액션 요망)
2. **인스타그램 파싱**: Jina Reader 외에 인스타그램 전용 크롤러(예: instaloader 등)로 파이프라인을 교체하거나 우회 방안 검토
3. **UI/UX (기획 준수)**: `/add` 페이지의 추출 결과창 하단에 `AdBanner` 추가 및 장소 클릭 시 네이버 검색/지도로 연결되는 버튼 추가 구현

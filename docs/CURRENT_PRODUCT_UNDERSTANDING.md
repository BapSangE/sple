# Sple 현재 제품 이해

_기준일: 2026-05-15_
_기준 소스: 공개 데모 `https://www.sple-insta.com` Playwright 점검_

## 1. 현재 서비스 정의

Sple은 인스타그램에서 발견한 맛집이나 장소 정보를 사용자가 텍스트로 복사해 붙여넣으면 AI로 장소 후보를 추출하고, 로그인 후 나만의 장소 컬렉션에 저장해 지도와 리스트에서 다시 찾는 PWA 서비스다.

문서와 코드에는 과거 방향인 “초경량 장소 추출 후 네이버 지도 연결 유틸리티”와 “나만의 핫플 지도/컬렉션 앱”이 함께 남아 있다. 실제 공개 데모 기준으로는 후자가 현재 제품 방향에 더 가깝다.

## 2. 공개 데모에서 확인한 실제 화면

### 지도

- URL: `/`
- Sple 로고와 네이버 지도 중심 화면을 보여준다.
- 하단에는 `지도`, `등록`, `리스트`, `프로필` 네 가지 탭이 있다.
- 서비스의 첫 인상은 단순 링크 변환기가 아니라 지도 중심 장소 앱이다.

### 등록

- URL: `/add`
- 화면 제목은 “장소 추출하기”다.
- 사용자는 인스타그램 캡션, 맛집 소개 글, 블로그 스니펫처럼 장소가 언급된 텍스트를 붙여넣고 `AI 분석하기`를 누른다.
- 인스타그램 URL 직접 분석은 봇 차단 가능성이 높아 제품 범위에서 제외한다.
- 공개 데모에서 샘플 장소 텍스트로 테스트했을 때 `서버 연결에 실패했습니다.`가 표시됐다.
- 따라서 프론트 UI는 배포되어 있으나 분석 API 연결 또는 환경 변수가 정상 동작하지 않는 상태로 보인다.

### 리스트

- URL: `/saved`
- “저장된 장소” 화면이다.
- 검색창과 `All`, `Cafe`, `Dining`, `Bar` 필터가 있다.
- 비로그인 상태에서는 “로그인 후 장소를 저장하고 확인할 수 있습니다.” 메시지를 보여준다.
- 이 화면은 저장형 개인 컬렉션 제품 방향을 뚜렷하게 보여준다.

### 프로필

- URL: `/profile`
- Google 로그인 버튼을 제공한다.
- 안내 문구는 “SPLE의 모든 기능을 사용하려면 구글 계정으로 로그인해주세요.”다.
- 로그인은 저장/리스트 기능의 전제 조건이다.

## 3. 현재 제품 방향

현재 방향은 다음 한 문장으로 정리한다.

> 인스타그램 캡션이나 맛집 소개 텍스트를 AI로 분석해 장소 후보를 뽑고, 사용자가 로그인해서 나만의 핫플 컬렉션에 저장한 뒤 지도와 리스트에서 다시 찾는 PWA 서비스.

## 4. 코드와 문서의 불일치

- `docs/REBOOT_PLAN.md`는 “초경량 네이버 지도 연결 유틸리티” 방향을 설명하지만, 공개 데모는 지도, 저장 리스트, 로그인 프로필을 유지하고 있다.
- `docs/QA_TEST_REPORT.md`는 통합 QA에서 서버/API, 지도 인증, 인스타 파싱 문제를 발견한 최신 상태를 잘 보여준다.
- 기존 백엔드에는 프론트가 호출하는 `/api/places` 저장/조회 API가 빠져 있었고, 이 문서 작성 시점에 복구 대상이 됐다.
- `/add`는 URL 분석이 아니라 텍스트 붙여넣기 분석을 기준으로 유지한다.

## 5. 우선순위

1. 텍스트 붙여넣기 기반 AI 추출 품질을 높인다.
2. 저장/조회는 인증된 사용자 세션을 기준으로 보호한다.
3. 저장된 장소가 지도 화면에서 어떻게 표현될지 정한다.
4. 제품 문서는 이 파일을 기준으로 정리하고, 과거 리부트 문서는 히스토리 문서로 격하시킨다.

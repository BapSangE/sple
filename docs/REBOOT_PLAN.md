# Sple Reboot: 초경량 장소 추출 유틸리티 작업 계획서

## 1. 개편 목표 (Core Objective)
기존의 무거운 자체 지도 렌더링 및 복잡한 아카이빙(저장, 폴더 등) 기능을 전면 폐기합니다. 오직 **"인스타그램 링크에서 장소를 뽑아 네이버 지도로 바로 연결해 준다"**는 단일 목적에 극도로 집중한 **초경량 유틸리티(Ultra-lightweight Utility)**로 재탄생합니다.

## 2. 핵심 워크플로우 (Core Workflow)
사용자의 조작 단계를 최소화한 **1-Depth 구조**를 가집니다.

1.  **Input (입력):** 사용자가 인스타그램 피드 링크를 복사하여 앱에 붙여넣거나, OS 공유 기능(Share Intent)으로 전송합니다.
2.  **AI Analysis (분석):** 백엔드에서 Gemini AI가 텍스트를 파싱하여 정확한 **상호명**과 **주소**만 빠르게 추출합니다.
3.  **Output (연결):** 추출된 장소 정보를 바탕으로 **네이버 지도 검색/길찾기 링크**를 생성하여 제공합니다.

## 3. UI/UX 개편 방향 (Design Overhaul)
디자인은 '기능'을 보조하는 수준으로 극한의 미니멀리즘을 추구합니다.

*   **제거 대상:** 카카오맵 캔버스, 하단 바(Bottom Nav), 복잡한 바텀 시트, 필터 칩, 폴더 분류 UI 등 전부 삭제.
*   **새로운 화면 구성 (단일 페이지):**
    *   **초기 화면:** 중앙에 큼직한 URL 입력창과 [장소 추출하기] 버튼만 존재.
    *   **로딩 화면:** "AI가 인스타그램에서 장소를 찾고 있습니다..."라는 직관적인 텍스트와 심플한 스피너.
    *   **결과 화면:** 추출된 장소명과 간략한 주소 텍스트, 그리고 거대한 **[네이버 지도로 보기]** 버튼 노출.

## 4. 단계별 실행 계획 (Phased Implementation)

### Phase 1: 기존 시스템 해체 및 청소 (Cleanup)
*   **Frontend:** `react-kakao-maps-sdk` 등 무거운 지도 관련 종속성 제거.
*   **UI Components:** `BottomNavBar`, `BottomSheet`, `FAB` 등 불필요한 컴포넌트 파일 삭제.
*   **Backend:** 데이터베이스 스키마 간소화. 복잡한 사용자 프로필, 즐겨찾기 폴더, 카테고리 로직 등 제거.

### Phase 2: 코어 파이프라인 재구축 (Backend Logic)
*   **Gemini 프롬프트 튜닝:** 불필요한 매력 포인트, 해시태그 추출 로직을 제거하고 오직 `상호명`과 `정확한 주소`만을 반환하도록 프롬프트 최적화. (응답 속도 향상)
*   **네이버 지도 딥링크 연동 로직:** 추출된 상호명과 주소를 쿼리로 변환하여 네이버 지도 검색 URL 포맷팅. (예: `https://map.naver.com/v5/search/{인코딩된_상호명_주소}`)

### Phase 3: 미니멀 UI 개발 및 통합 테스트 (Frontend)
*   입력 -> 추출 -> 결과 확인으로 이어지는 매끄러운 단일 화면 트랜지션 구현.
*   모바일 환경에서 Share Intent로 URL을 넘겨받았을 때, 사용자의 추가 클릭 없이 바로 로딩 및 결과 화면으로 넘어가도록 UX 최적화 (Zero-Click Flow).

## 5. 기대 효과
*   **개발/유지보수 비용 감소:** 지도 API 의존성과 복잡한 상태 관리가 사라져 코드베이스가 획기적으로 가벼워집니다.
*   **사용자 편의성 극대화:** 무거운 앱을 켜서 지도를 볼 필요 없이, 필요한 장소만 빠르게 네이버 지도로 넘겨서 기존에 익숙한 내비게이션, 리뷰 확인 시스템을 그대로 활용할 수 있습니다.
